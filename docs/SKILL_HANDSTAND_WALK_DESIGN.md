# 물구나무 보행 기술 정책 설계 (초안)

- 날짜: 2026-11-09
- 목표: 네 발로 선 상태에서 외부 모드 신호를 받아 **앞발 물구나무 → 앞발 두 개로 2–3 m 보행 → 정지 → 네 발로 복귀**.
- 출발 모델: ⓪ DWB-38000 (블라인드, `checkpoints/00_blind/0_blind_walk_a6000/teacher/model_38000.pt`).
- 원칙: 걷기 정책(⑥ it861)과 섞지 않는 **별도 기술 정책**. 새 패키지에서만 작업하고 기존 학습 코드는 건드리지 않는다.

## 1. 확정 사항 (사용자 11-09)

| 항목 | 결정 |
|---|---|
| 기술 | 앞발 물구나무 상태에서 이족 보행 |
| 거리 | 2–3 m 보행 후 네 발로 복귀 |
| 적재 | 0 kg |
| 센서 | 고유감각만. LiDAR·카메라 입력 없음, LiDAR 장착 없음 (질량은 URDF 40.7 kg) |
| 실행 | 외부 모드 전환 신호 (2.3) |

미정: 뒷발 서기도 걸어야 하는지 / 중단했을 때 목표(이 문서는 **가장 빠른 네 발 복귀**로 가정).

## 2. 시스템 구조

### 2.1 정책 전환

```
WALK(⑥ 861) ─정지·조건 확인─▶ SKILL_READY ─▶ SKILL_RUN(물구나무 보행 정책) ─▶ SKILL_EXIT ─▶ WALK
                                  │ 조건 불충족: 거부          │ 고장·신호 끊김: 정책 안에서 나오기 → 실패 시 Damp
```

- 중단도 정책을 갑자기 바꾸지 않는다. 항상 기술 정책이 스스로 네 발로 내려온 뒤 걷기 정책으로 넘긴다.
- SKILL_READY → RUN: 걷기 정책의 선 자세와 기술 정책 시작 자세의 관절 목표를 0.3 s 동안 섞는다.

### 2.2 Pilot 모드 관리자 진입·종료 조건

| 전환 | 조건 |
|---|---|
| WALK → READY | 몸 속도 < 0.05 m/s, yaw 회전 < 0.1 rad/s, 네 발 접촉, 기울기 < 5°, 모터 온도 정상 |
| RUN → EXIT | 외부 EXIT(속도 명령 0을 0.5 s 확인한 뒤), ABORT, 하트비트 300 ms 끊김, 유지 상한(20 s), 토크 포화 지속, 기울기 한계 초과 |
| EXIT → WALK | 네 발 접촉 + 선 자세 안정 0.5 s. 2 s 안에 안 되면 Damp |

### 2.3 외부 신호 MOD1 (UDP, 10 Hz 하트비트)

| 필드 | 값 |
|---|---|
| `mode` | 0 = 걷기, 2 = 물구나무 보행 (1 = 뒷발 서기 예약) |
| `request` | ENTER / EXIT / ABORT |
| `vx, vy, wz` | 물구나무 중 속도 명령 (2.4의 좌표계) |
| `seq, stamp` | 중복·순서 확인, 지연 측정 |

거리 2–3 m는 gdm이 odom으로 재고 EXIT를 보낸다. 정책은 거리를 모른다(블라인드, 위치 입력 없음).

### 2.4 속도 명령 좌표계

물구나무 때 몸 x축은 아래를 향하고 등이 원래 진행 방향을 본다. 몸 좌표계를 그대로 쓰면 앞뒤가 뒤집히므로, **ENTER 순간의 진행 방향(yaw)에 고정한 수평 좌표계**에서 명령을 정의한다. vx+ = 원래 앞, ωz = 위에서 본 회전. 정책에는 이 좌표계로 변환한 명령을 넣는다(Pilot·학습 공통 변환).

## 4. 관측과 행동

| | 내용 | 크기 |
|---|---|---|
| Actor | 고유감각 46 × 4 (명령 칸은 0, 적재 0) | 184 |
| | CENet z (속도 3 + 맥락 16) | 19 |
| | 모드 명령: [요청 on/off, 중단 플래그, 명령이 바뀐 뒤 지난 시간/3 s (0–1로 자름)] | 3 |
| | 속도 명령 (vx, vy, ωz), 2.4 좌표계 | 3 |
| Critic | DWB 특권 관측 + 발별 접촉력 + 몸 높이 + 목표 자세 오차 + 위상 정답 | |
| 출력 | 관절 12 → PD. action scale 0.25로 시작, 자세 도달이 막히면 0.4로 검토 | 12 |
| 초기화 | DWB-38000 가중치 + 새 입력 6열을 0으로 → 처음에는 DWB처럼 선다 | |

## 5. 에피소드와 명령 무작위화

에피소드 20 s (DWB와 같음). 명령은 시간표가 아니라 **외부 신호처럼** 무작위로 준다.

| 사건 | 분포 |
|---|---|
| ENTER | 0.5–3 s |
| 물구나무 안정 후 속도 명령 시작 | ENTER 후 2–4 s |
| 보행 | vx 0.1–0.3 m/s를 6–12 s (= 0.6–3.6 m), 중간에 ωz ±0.5, vy ±0.1 구간 섞기 |
| 정지 | 속도 0을 1–2 s → EXIT |
| ENTER 없이 끝까지 서 있기 | 15 % |
| 들어가는 도중 ABORT | 15 % (자세 20–80 % 진행 지점) |
| 걷는 중 ABORT | 10 % |
| 신호 품질 | 지연 0–100 ms, 300 ms 이상 끊김 = EXIT |

요청 on / off / 중단 샘플이 모두 자주 나와야 정책이 신호를 읽는다 (B′ 교훈, 통합 문서 7.4).

## 6. 보상 (초기 가중치, 학습하며 조정)

게이트는 시간이 아니라 **명령 상태**로 켠다. 판정은 필터한 속도·자세로 한다(회전 실험 교훈).

| 분류 | 항목 | 켜지는 상태 | 초기 가중치 |
|---|---|---|---|
| 자세 | 몸 기준 중력 방향이 물구나무 목표(몸 x축 = 아래)에 가까움, exp(−e²/0.1) | 요청 on | +3.0 |
| | 엉덩이(뒤쪽) 높이 목표 | 요청 on | +1.0 |
| 접촉 | 앞발 두 개만 접촉 | 요청 on, 자세 도달 후 | +1.0 |
| | 뒷발 접촉 | 요청 on, 자세 도달 후 | −2.0 |
| | 몸통·허벅지·무릎·머리 접촉 | 항상 | −10 + 종료 |
| 보행 | 속도 추종 (vx, vy, ωz) × 자세 보상 계수 | 속도 명령 ≠ 0 | +2.0 / +1.0 |
| | 앞발 교대 체공 시간 (0.25–0.4 s), 두 발 동시 체공 벌점 | 속도 명령 ≠ 0 | +1.0 / −1.0 |
| | 들어 올린 발 높이 3–6 cm, 착지 충격, 발 미끄러짐 | 속도 명령 ≠ 0 | +0.5 / −0.01 / −0.5 |
| | 속도 0이면 두 발 접지 정지 | 요청 on, 명령 0 | +1.0 |
| 균형추 | 뒷다리 관절 움직임 벌점 없음 (한계·충돌만) | 요청 on | 0 |
| 복귀 | DWB 기본 자세 오차, 네 발 접촉 | 요청 off·중단 | +2.0 / +1.0 |
| 서기 | 요청이 없으면 움직이지 않음 (자세 변화 벌점) | 요청 없음 | −1.0 |
| 정규화 | 토크², 관절 가속도, 행동 변화율, 관절 한계, 전력 | 항상 | DWB 값 |
| | **토크 포화 시간** (한계 90 % 이상) | 항상 | −1.0 |
| | 무릎 펴기 유도 (−0.6 ~ −0.9 rad 밖이면 벌점) | 앞다리 한 발 지지 | −0.5 |

## 7. 탐색 보조 장치

| 장치 | 방법 | 줄이는 기준 |
|---|---|---|
| 보조 힘 | 몸통에 가상의 들어 올리는 힘과 pitch 토크 (처음 체중의 50 %) | 단계 성공률 ≥ 70 %마다 25 %p씩 → 0 |
| 목표 각도 커리큘럼 | 목표 pitch 30° → 60° → 75° → 90° | 성공률 ≥ 70 % |
| 중간 상태에서 시작 | 에피소드의 25 %를 기울어진 자세(물구나무 진행 30–100 %)에서 시작 | 들어가기 성공률 ≥ 80 %면 10 %로 |
| 키프레임 안내 | 물구나무 최종 관절 각도로 약한 모방 보상 | 3단계부터 0 |

## 8. 기존 동작 보존

- **서기 앵커**: 요청 없음 구간에서는 DWB-38000의 행동으로 회귀하는 앵커 손실 (`anchor.py`의 서기 앵커와 같은 방식, 고정된 DWB 복사본이 목표).
- **좌우 대칭 증강** 사용 (물구나무 보행은 좌우 대칭).
- 도메인 무작위화: DWB와 같게 (마찰, 질량 ±, 게인, 지연). 밀기 외란은 보행 단계부터 약하게.

## 9. 커리큘럼과 통과 기준

| 단계 | 내용 | 통과 기준 (결정론적 평가) |
|---|---|---|
| S1 | 들어가기·유지 (보조 힘 → 0) | 물구나무 도달 ≥ 90 %, 5 s 유지 ≥ 90 % |
| S2 | 제자리 걸음 | 넘어짐 없이 5 s ≥ 90 % |
| S3 | 앞으로 0.1 → 0.3 m/s | **3 m 완주 ≥ 90 %** |
| S4 | 회전·옆걸음 섞기 | 속도 추종 오차 < 0.1 m/s, 3 m ≥ 90 % |
| S5 | 정지 → 네 발 복귀, 걷는 중 ABORT | 복귀 ≥ 95 %, 넘어짐 0 |

갭 실험과 같이 **90 % 이상**을 실전 기준으로 둔다.

## 10. 평가

- Isaac 결정론적 평가 (E2 방식): 단계별 성공률, 3 m 완주율, 속도 추종 오차, 최대 토크·포화 시간, **중단 행렬**(들어가기 0–100 %, 보행 중 시점별 ABORT).
- 요청이 없을 때 오동작 0 %.
- 861 → 기술 → 861 왕복 20회.
- MuJoCo: Pilot 모드 관리자 + MOD1 송신기로 같은 시나리오 (배포 저장소 작업).
- 실기: 안전 줄 + 매트, Supervisor Damp 연동.

## 11. 학습 서버와 규모

- 로컬 1 GPU 시험: 1,024 env × 30 it (보상·종료·보조 힘 동작 확인).
- A6000 (GPU 0–2): 5,120 env. S1–S2를 먼저 하고, S3 이후 진행이 느리면 한강을 검토.
- 블라인드라 레이캐스트·LiDAR 계산이 없어 지금 학습보다 iteration이 빠를 것으로 예상.
