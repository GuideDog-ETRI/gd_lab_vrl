# 원래 3906 기반 후진 갭 극복 학습 설계안 (초안, 2026-10-22)

상태: **확정·구현 (2026-10-22)**. 코드: `src/gd_lab/gast_backgap/`, `scripts/gast_backgap/`, `configs/gast_backgap/` (브랜치 `feat/gast-backgap`). 기존 3906 코드는 바꾸지 않았다.

## 1. 목표

- 원래 3906(Ray+IR, sha `f3e7afe5…`)에서 시작해, **후진할 때도 갭에 빠지지 않고 건너는** 교사 정책을 만든다.
- 전진 갭, 계단, 하중·외력 성능은 3906보다 나빠지지 않아야 한다(비열등).
- 학습 장소: 로컬 5090 서버(GPU 1장, 32 GB).

## 2. 현재 3906 상태 (코드·기록 확인 결과)

| 항목 | 확인 결과 | 후진 갭에 대한 의미 |
|---|---|---|
| 명령 범위 | 일반 지형은 vx −1.2~1.2 m/s, vy ±1.0, ωz ±1.0 | 평지·거친 지형에서는 이미 후진을 배웠다 |
| 갭 타일 명령 | `BoardingVelocityCommand`: heading을 ±x로 고정하고 **vx를 +0.2~0.6 m/s로만** 준다. 옆 명령은 0 | **갭을 뒤로 건넌 경험이 없다** |
| 갭 타일 기하 | 8 × 8 m 타일 중앙에서 ±x 방향 시작. 갭 중심 ±1.5 m, 폭 0.02~0.26 m, 단차 0~0.16 m, 깊이 0.65 m. 갭 열은 전체 20열 중 10열 | 시작 위치 앞뒤 양쪽에 갭이 있어 명령 부호만 바꾸면 뒤쪽 갭으로 간다 |
| 갭 보상 | 건넘(`platform_gap_crossing`)·빠짐·침범·clean·발 디딤 여유는 발 위치 기하로 계산하고 방향을 가리지 않는다 | 그대로 쓸 수 있다 |
| 뒷다리 전용 항 | `gap_hind_hop`(뒷발 두 개가 동시에 뜨는 점프)만 뒷다리 전용이다 | 후진 때는 뒤따르는 다리가 앞다리이므로 앞다리 대칭 항이 필요하다 |
| 지형 입력 시야 | 11 × 17칸(10 cm), x ±0.8 m, y ±0.5 m. 카메라 4대(앞 2, 뒤 2) 기준 관측 칸은 몸 중앙 띠(y ±0.2 m)이고 **앞뒤 대칭으로 ±0.8 m까지** 보인다 | 뒤로 갈 때도 몸 중심 뒤 0.8 m(뒷발 뒤 약 0.5 m)까지 보인다. 0.4 m/s면 약 1.2 s 앞을 본다 |
| 지형 기억 | 8프레임, 최근 4.8 s | 뒤쪽 갭이 시야에 들어온 뒤 기억으로 이어진다 |
| 3906 학습 규모 | 90.111 5090 1장에서 1024 env × 100 step × 5000 update, 16.4 시간 | 같은 급 GPU에서 1024 env는 검증된 값이다 |

## 3. 변경안

모든 변경은 **새 task와 새 파일**로 만든다. 기존 3906 학습 코드는 고치지 않는다.

### 3.1 명령 (핵심)

- 갭 타일에서 확률 `p_back`으로 **후진 명령**을 준다. |vx|는 전진과 같은 v2.1 속도 분포(0.2~1.2 m/s, 속도 상한 ramp)에서 뽑되 **1.0 m/s로 제한**한다. 즉 vx ∈ [−1.0, −0.2] m/s(사용자 결정 2026-10-22). vy = 0, heading은 지금처럼 ±x로 고정한다.
- 나머지 `1 − p_back`은 지금과 같은 전진 명령이다.
- `p_back`은 0.4에서 시작해 **0.7**까지 올린다(첫 200 update에 걸쳐). 사용자 결정(2026-10-22): 후진 갭 비율을 높인다. 전진 갭은 갭 타일의 30%(전체 env의 약 15%)로 유지해 망각을 막는다.
- 계단·일반 지형 명령은 바꾸지 않는다.

### 3.2 보상

- 기존 갭 보상은 그대로 쓴다. 기하 기반이라 방향을 가리지 않는다.
- `gap_front_hop`을 추가한다: 후진 명령일 때 앞발 두 개가 동시에 뜨는 점프에 대한 페널티이고, `gap_hind_hop`과 같은 가중치 −1.0이다.
- `gap_hind_hop`은 전진 명령에서만 켠다. 후진 때는 뒷다리가 앞서 가므로 의미가 다르다.
- 후진 속도 추종은 기존 `track_lin_vel_xy_exp`가 그대로 맡는다.

### 3.3 지형·커리큘럼

- 갭 폭 커리큘럼은 지금 방식(건너면 올리고, 빠지면 내림)을 유지한다.
- **단차는 전진과 동일**(0~0.16 m, 같은 커리큘럼, 사용자 결정 2026-10-22). 후진 전용 상한은 두지 않는다.
- 갭 레벨 통계는 전진과 후진을 나눠 기록한다.

### 3.4 초기화와 학습률

- 3906 Top-1 가중치에서 시작한다. PPO·CENet optimizer는 새로 만든다.
- 정책 학습률은 1e-4(3906과 같음)이다. 지형 encoder는 3e-4로 낮춰 전진 갭 표현이 흔들리지 않게 한다.
- 행동 노이즈 std는 3906 값을 그대로 이어받는다.

### 3.5 망각 방지

- 갭 열 50%, 계단과 기존 지형 비율은 3906과 같게 둔다.
- 전진 갭은 `1 − p_back` 비율로 계속 학습한다.

### 3.6 Top-5 (사용자 규칙: 매 iteration 비교, 간격 없음)

- 점수: 후진 갭 clean 성공, 전진 갭 clean 성공, 1회 접촉 성공(B)을 합한다.
- gate:
  - 전진 갭 성공 ≥ 3906 − 0.02
  - 계단 종료율 ≤ 0.09
  - base contact ≤ 0.09
- 주기 저장은 100 update마다이고, Top-5와 별개다.
- 기준 파일은 학습 중에 바꿀 수 있게 한다.

### 3.7 평가

1. Isaac E1에서 전진과 후진 갭 5~30 cm를 같은 조건으로 비교한다.
2. MuJoCo force4 코스를 후진 버전으로 만들어 센서 sidecar(depth + IR)로 확인한다.
3. 3906과 비교한다: 전진 갭, 계단, 하중 6 kg + 외력 150 N.

## 4. 학습 규모 (이 서버)

| env | GPU 최대 메모리 | update당 시간 | 결과 |

## 6. 위험

- 실제 로봇 sidecar 매퍼(v25or)가 뒤쪽 칸을 시뮬레이터만큼 채우는지 확인해야 한다. 로봇이 뒤로 갈 때 뒤 카메라의 갭 검출이 앞 카메라와 같은지 rosbag으로 확인한다.
- 후진 단차 내리막(뒷다리가 먼저 내려감)에서 넘어질 수 있다.
- 갭 비율 중 후진이 늘면서 전진 갭 성능이 떨어질 수 있다(망각). Top-5 gate로 막는다.
