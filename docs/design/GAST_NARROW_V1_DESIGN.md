# GAST-Narrow v1 설계 (2026-10-26)

backgap V2 update 6566(최종 Top-1)을 백본으로, **좁은 통로 통과만** 추가 학습한다. GAST-Nav v1(다중 GPU, 3기능)은 서버 수리로 멈춘 상태 그대로 두고, 그 코드는 건드리지 않는다.

## 1. 사용자 결정 (2026-10-26)

| 항목 | 결정 |
|---|---|
| 백본 | backgap V2 6566 (`backgapv2_6566.pt`, sha256 `22cf918c…ba78`) |
| 기능 | 좁은 통로 통과만 (제자리 회전·계단참 없음) |
| 명령 | gdm이 직진·회전 명령을 준다고 가정 |
| 센서 | Ouster OS1-64 + Mid-360, sim_docker와 같은 장착·사양 |
| 뎁스 | 배 아래 D4xx는 발 주변 0.44 m만 보여 벽 판단에 도움이 안 됨 → 기존 지형 입력으로만 둔다 |
| 학습 | 90.111 5090 1대, 1024 env × 100 step, 3000 update |

## 2. 정책 구조

```
6566 그대로:  고유감각 46×4 + CENet code + 배 아래 Ray+IR 지형 latent 32 ─┐
새로 추가:    머리 LiDAR 점유 지도 [2,30,48] → CNN → latent 16 ─────────────┴→ actor (새 입력 열 0 초기화)
critic:       기존 critic 입력(정규화) + 특권 6 [d_left, d_right, lateral, heading err, progress, flag] (새 열 0)
```
- 시작 시 actor·critic 출력은 6566과 같다(새 열이 0).
- LiDAR 인코더는 terrain 학습률 그룹(3e-4), 나머지는 1e-4. PPO optimizer는 새로 만들고, CENet optimizer와 기존 지형 단계는 복원한다.
- 좌우 대칭 증강: 지도는 y축 뒤집기, 특권은 좌우 교환·부호 반전.

## 3. LiDAR 입력 (`gast_narrow/lidar.py`)

| 항목 | 값 |
|---|---|
| Ouster OS1-64 | os_sensor (0.285, 0, 0.046), rpy (0, 0.74°, 0.50°), 레이 원점 +0.036 m. 64빔 ±22.5° × 256열, 최소 0.5 m |
| Mid-360 | livox_frame = os_sensor ∘ (−0.0207, 0.0387, 0.1426), rpy (0.02°, 4.81°, 0). −7~52° 24줄 × 160열, 캡처마다 무작위 지터(비반복 근사), 최소 0.1 m |
| 주기·잡음 | 10 Hz(env마다 위상 무작위), 거리 잡음 1 cm, 점 5% 누락, 프레임 3% 누락(이전 유지), 장착 ±1 cm·±1° (에피소드마다) |
| 지도 | 몸 yaw 기준, x −0.9~1.5 m, y −0.75~0.75 m, 5 cm → 30×48. 발 기준 지면 위 0.08~1.0 m 반사점이 있으면 1. [이전, 현재] 2프레임 |

검증: 흰 점이 실제 벽(빨강)의 로봇 쪽 면에 찍히는 것을 그림으로 확인했다(`scripts/gast_narrow/inspect_narrow.py`).

## 4. 장면 (31열 × 15단계, 8 m 타일)

| 구분 | 열 | 내용 |
|---|---|---|
| 기존 유지 | 13 | 6566의 11종. platform_gap 3열, 나머지 1열씩. 보상·명령은 6566 그대로 |
| corridor | 4 | x −1.5~2.5 직선 복도 |
| door ± | 3+3 | 문 두 개(x 0~0.2, 1.6~1.8), 둘째 문이 ±0.25 m 옆으로 어긋남 |
| bend 좌/우 | 4+4 | x 1.0에서 90° 꺾임 |

- 폭: 단계 0의 1.20 m부터 단계 14의 0.60 m까지(swept 폭 0.50 m 기준). 벽 두께 0.1 m, 높이 1.0 m.
- 시작: (−2.2, ±0.15 m), yaw ±15°.
- 성공: 출구선 통과(corridor x>2.8, door x>2.3, bend |y|>2.6). 0.5초 뒤 time-out 종료.
- 커리큘럼: 벽 접촉 0.2초 미만으로 통과하면 단계를 올리고, 몸통 접촉이나 실패면 내린다.

## 5. 명령 (gdm 근사, `NarrowVelocityCommand`)

- **속도:** vx는 0.35~0.6 m/s(에피소드 고정), vy는 0.
- **회전:** ωz = clip(1.5·(0.5 m 앞 경로 접선 yaw + 편향 − yaw), ±0.6). 편향은 에피소드마다 ±8°이고, 5 Hz로 갱신하며 잡음 σ 0.05를 넣는다.
- **옆 오차:** 명령에 넣지 않는다. 벽에서 떨어지는 것은 정책이 LiDAR로 맡는다.
- **통과 후:** 명령을 0으로 둔다.

## 7. Top-5 (매 update, 간격 1, 150부터)

- **점수:** 0.40·S + 0.15·W + 0.15·G + 0.20·B + 0.10·T
  - S: 좁은 통로 통과율
  - W: 벽 무접촉률
  - G: 갭 clean 통과율
  - B: 1 − 몸통 접촉률
  - T: 기존 타일 추종
- **조건:** 좁은 통로 평균 단계 ≥ 3, 몸통 접촉률·갭·계단 종료율 ≤ 9%, 갭 평균 단계 ≥ 8. 조건은 `configs/gast_narrow/online_top5.json`에 있고 학습 중에도 바꿀 수 있다.

## 8. 실행

```bash
scripts/gast_narrow/train_narrow_1gpu.sh smoke 0     # 64 env × 16 × 5
scripts/gast_narrow/train_narrow_1gpu.sh pilot 0     # 1024 × 100 × 50 (시간 측정)
scripts/gast_narrow/train_narrow_1gpu.sh train 0     # 1024 × 100 × 3000
touch logs/launches/<run>/STOP                       # 저장 후 정지
```

## 9. 위험

- **기존 능력 저하:** 갭 비율이 50%에서 10%로 줄어 갭·계단 능력이 떨어질 수 있다. G·B를 점수와 조건에 넣었고, 학습 후 6566 갭 평가로 다시 확인한다.
- **센서 근사:** 실제 Ouster와 Mid-360 패턴을 근사했다. 실 로봇의 자기 몸 반사 제거나 근거리 사각은 sim_docker와 실 로봇에서 따로 확인한다.
- **배포 계약:** export·Pilot 쪽 LiDAR 입력 계약은 아직 없다. 학습 결과를 보고 만든다.
