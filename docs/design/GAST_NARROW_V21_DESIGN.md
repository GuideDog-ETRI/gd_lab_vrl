# GAST-Narrow v2.1 설계 (2026-10-27)

v2 Top-1 **1111**에서 출발한다. 서기와 통과 능력은 그대로 두고, 갭 성능을 6566 쪽으로 되돌리며, 통로 과속을 막는다.

## 1. 배경 (E2, seed 42)

| 항목 | 6566 | 1748 | 1111 |
|---|---|---|---|
| 전진 갭 clean (시도당) | 77% | 61% | 69% |
| 후진 갭 clean, 라이다 켬 | 72% | 77% | 74% |
| 후진 갭 clean, 라이다 끔 | 76% | 66% | 68% |
| 계단 통과 | 91.5% | 91.0% | 92.2% |
| 좁은 통로 통과 시간 중앙값 (약 5.5 m, 명령 평균 0.58 m/s) | 11.0 s | 6.1 s | 6.5 s |

- 갭 성능 하락은 v1에서 시작됐다. 갭 열이 3906·6566의 절반에서 31열 중 3열로 줄었다.
- v1과 v2는 통로를 명령보다 약 1.5배 빠르게 지난다.
  - 통과 보상(+8)을 받으면 에피소드가 끝나서, 빨리 지날수록 이득이었다.
  - MuJoCo에서 머리 라이다를 켜면 2~4 m/s로 질주한다. 라이다를 끄면 1.6 m/s이고, 6566은 0.9 m/s다.

## 2. 변경 (v2 대비, 이것만)

| 항목 | 내용 |
|---|---|
| 지형 | platform_gap 3 → 8열 (36열 중 22%). 나머지는 v2와 같다 |
| 6566 고정 증류 | 매 update의 PPO 단계 뒤에 한 번 더 학습한다. 좁은 통로 타일이 아닌 샘플에서 `‖μ_policy − μ_6566‖²`(행동 평균)을 줄인다. 가중치 1.0, epoch 1. 6566은 현재 정책 사본에 6566 가중치(라이다·여유 열 0)를 넣어 그대로 재현한다 (`gast_narrow/anchor.py`) |
| 통로 과속 벌점 | `narrow_overspeed`: 좁은 통로 타일에서 평면 속도가 \|명령\| + 0.15 m/s를 넘으면 그 초과분만큼 초당 −2 |
| 출발 | 1111. 모든 가중치를 그대로 복사한다. PPO 최적화기는 새로 만들고, CENet 최적화기와 지형 단계는 복원한다 |
| 규모 | onvlm2 GPU 0·1·2, 4096 env × 100 step × 700 update, 약 21.5 s/update |

명령, 입력, 좁은 통로 타일, Top-5 점수와 조건은 v2와 같다.

## 3. 실행

```bash
scripts/gast_narrow/train_narrow_v21_3gpu.sh smoke|pilot|train
# NARROW_ANCHOR_CKPT (기본 checkpoints/gast_narrow/backgapv2_6566.pt), NARROW_ANCHOR_WEIGHT, NARROW_ANCHOR_EPOCHS
```

## 4. 판정

- 학습이 끝나면 Top-5를 6566·1111과 함께 E2(`configs/gast_narrow/e2/v2_top5.yaml` 모델 목록만 바꿈)로 평가한다.
- 목표:
  - 전진·후진(라이다 끔 포함) 갭 clean이 6566보다 2%p 넘게 떨어지지 않는다.
  - 서기·통과는 1111 수준이다.
  - 통로 통과 시간이 명령 속도에 맞는다.
- MuJoCo `narrow_only` 코스에서 질주가 사라졌는지 확인한다.
