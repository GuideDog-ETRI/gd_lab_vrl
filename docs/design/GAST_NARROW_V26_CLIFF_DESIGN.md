# GAST-Narrow v2.6 (C1): 낭떠러지 정지 — 설계 초안 (2026-11-02)

단계 순서 A′(갭·보행 v3) → B′(통로, 전후진) → **C1 = 낭떠러지 정지(v2.6)** → C2(제자리 회전).
출발 모델은 B′ 최종 모델(한강 lineage16_bprime)이고, 사전 검증은 A6000에서 B′ 이어 학습 모델로 한다.
v2.5 설계(`GAST_NARROW_V25_DESIGN.md` §3)의 타일·구역·보상은 그대로 쓰고, 이 문서는 **v25b가 실패한 두 가지**
— (1) 정지를 한 번도 찾지 못한 탐색 문제, (2) 방향별 인지 한계 — 를 측정값으로 다시 정한다.

## 1. 질문과 측정 (2026-11-02, 로컬 Isaac replay)

사용자 질문: "앞뒤좌우 갭·계단과 낭떠러지 구분을 하방 뎁스 FOV로 커버 가능한가? 학습하면 갭·계단이 퇴화하지 않나? 최적의 방법은?"

측정 방법: `logs/rl_replay/c1_*.json`, 분석 `scratchpad/focus/c1_probe.py`, `c1_probe2.py`.
- 갭 L14(폭 0.244~0.26 m, 깊이 0.65 m): g5fin(A′), 전진 0.5 / 후진 −0.5 m/s, 32 env × 10 s.
- 낭떠러지 데크(v2.5 `narrow_cliff`, 1.0 m 낙차, 사방): bpfin(B′), 명령 앞·뒤·좌·우, 32 env × 12 s (+ 갭 2열).
- 교사 지형 입력(하방 Depth+IR 가시 스캔, 11 × 17, 몸 중심 x ±0.8 / y ±0.5 m)에서 명령 방향 셀 줄을 읽어, 끝선까지의
  거리별로 "낙차 셀이 보이는가", "낙차 너머 바닥(건너편)이 보이는가"를 셌다. 보이지 않는 셀은 높이 0(= 평지)로 들어온다.

| 문제 정의 | 결과 | 반영 방향 |
|---|---|---|
| 하방 뎁스가 앞·뒤 낭떠러지를 어디서부터 보는가 | 낙차 셀 가시: 끝선 0~0.3 m 앞 97~100 %, 0.3~0.6 m 38 %(앞) / 60 %(뒤), **0.6 m 밖 0 %** | 인지 거리 ≈ 0.6 m. v2.5의 구역(e < 0.6 m)은 맞다. 0.3~0.8 m/s에서 반응 시간 0.75~2 s |
| **좌·우** 낭떠러지 | 좌·우 낙차 셀 가시 **0 %**(모든 거리). 평지에서도 옆 0.27 m 밖은 전부 미가시(몸·다리 가림, 카메라는 앞·뒤만) | 하방 뎁스로는 옆 낭떠러지를 **볼 수 없다**. 교사 기억(history 0.48 s)으로도 못 메운다. → D1 |

**결론(사용자 질문에 대한 답):**
- 앞·뒤: 하방 뎁스로 구분 **가능**. 구분 근거는 FOV가 아니라 "건너편 바닥 가시 + 낙차 깊이"이고, 세 지형의 특징이 겹치지 않으므로
  갭 열·앵커를 유지하면 갭·계단 퇴화 위험은 작다(사전 검증 관문으로 확인, §6).
- 좌·우: 하방 뎁스로는 **불가능**(0 %). 좌우를 학습시키면 "옆 명령 + 미가시 = 정지"를 배워 옆걸음 전부가 무너진다.
  옆 낭떠러지는 gdm·감독 센서(전방 Ouster, Mid-360)의 책임으로 두고 v2.6에서 제외하는 것을 권한다(D1).
- 탐색: v25b·bpfin 모두 정지를 한 번도 샘플하지 못했다. v2.4c에서 통한 "critic 입력을 actor로" 패턴을 **센서에서 계산되는
  특징**으로 쓴다(D2). 장소 라벨이 아니라 입력에서 유도되는 양이라 설계 원칙(gdm이 어디를 정하고, 보행 정책 입력은 옮기지 않음)과 충돌하지 않는다.

### 2.1 `support_end` 특징의 측정 근거

| 상황 (끝선 거리) | "너머에 가시 바닥 없음" 비율 | 의미 |
|---|---|---|
| 낭떠러지 앞·뒤, ≤ 0.6 m | 96~100 % | 특징이 거의 항상 켜진다 |
| 평지(데크 중앙) 앞·뒤 | 1~11 % | 오경보 하한 |
| 갭 L14 앞, 0~0.3 m | 22 % (건너편 가시 78 %) | 갭 근접에서도 1/5은 켜진다. 입력일 뿐 하드 게이트가 아니고, 깊이 값(0.65 vs 1.0)과 갭 패턴으로 정책이 걸러야 한다 |
| 갭 L14 앞, 0.3~0.6 m | 45 % | 가장 모호한 구간. 갭 열·앵커 유지가 필요한 이유 |

갭 타일의 착지 단차(±0.16 m) 때문에 "바닥" 판정 문턱(|h| < 0.15)이 과하게 걸려 갭 값은 과대 추정이다. 구현 시 문턱을 0.25로
두고 사전 검증 시작 점검에서 갭 열의 특징 켜짐 비율을 기록한다. 대안(D2 보류안): 구역 안 명령을 처음엔 0으로 주고 점차 유지하는
단계형 명령(입력 변경 없음), 서기 앵커를 낭떠러지 구역 표본에만 적용(v2.4e의 통로 흔들림 문제는 구역이 명확해 재발 가능성 낮음).

## 3. 구현 범위 (모두 새 패키지 `gd_lab.gast_cprime` + gast_bprime 소폭)

### 3.1 바닥 처리 마스크 (필수)
- `gast_bprime/terrain_obs.py`: 지형 **입력**의 평면화 범위만 `passage_mask(env) = narrow & (kind != CLIFF)`로 제한한다
  (데크 원점은 데크 윗면이라 평면화하면 낙차가 사라지고 동일 높이 검사가 깨진다). B′(낭떠러지 열 0)에서는 값이 같다.
- `gast_gait/terms.narrow_floor`(R1/R6/R15의 바닥 기준)는 **그대로 둔다**: 데크는 평평하고 env 원점 z가 데크 윗면이므로
  낭떠러지 타일에서도 "바닥 = 원점 z"가 맞다. 허공 광선이 R1 기준을 끌어내리는 문제(§4)는 이 경로에서는 생기지 않는다.
  → A′·B′ 보상 코드는 변경 없음(한강 B′ 코드 영향 0).
### 3.2 태스크 `GastNarrowCPrimeTeacherCfg(GastNarrowBPrimeTeacherCfg)` (`gd_lab.gast_cprime.tasks`)
- 실행 스위치 `NARROW_TURN=0 NARROW_CLIFF_COLUMNS=4` → 44 + 4 = 48열(tasks_v25가 열을 만든다; cfg가 검사).
- `gast_cprime.cliff.reset_cliff_cprime`: v2.5 `reset_cliff` 뒤에 방향 (0.5, 0.5, 0, 0)·속도 0.3~0.8을 다시 뽑는다
  (v2.5 상수는 건드리지 않음, margin.py와 같은 방식).
- 관측 그룹 `narrow_support_end`(1열, `gast_cprime.support.SupportEnd`) + actor `GastNarrowCPrimeActorCritic`
  (v2.4c 위에 0 열 1개) + 미러는 값 복사(중심선 값이라 좌우 대칭).
- `support_end` 규칙(§2 수정): 중심선 셀을 몸에서 바깥으로 8칸(0.1~0.8 m) 따라가며 "보이고, 직전 지지 셀보다 0.35 m 이상
  낮지 않은" 셀을 지지(support)로 본다. 계단 한 단(≤ 0.2 m)·갭 건너편(보이면)은 지지, 데크→바닥 낙차(1.0)·갭 바닥(0.65)·
  안 보이는 셀은 비지지. 첫 비지지 셀 거리 d 너머에 지지 셀이 없으면 (0.8 − d)/0.8, 있으면 0. 명령이 옆/정지, 프레임 전체가
  꺼진(blackout) 때는 0. 설계 초안의 절대 문턱(|h| < 0.25)은 계단 내려가기에서 값이 켜져(두 단 아래가 0.3) 바꿨다.
- 로더(`scripts/gast_cprime/train_cprime.py`): B′ 체크포인트 → actor.0.weight +1 열(0), PPO 새로; C′ → 이어 학습(PPO 복원).
### 3.3 스크립트·E2
- `scripts/gast_cprime/train_cprime{.py,_3gpu.sh}`(B′ 복사), `lineage16_b.sbatch`에 `cprime)` 케이스.
- E2: `cliff` suite(방향 앞·뒤 × 레벨 7/14 × 속도 0.3/0.8, hold·breach·fall) — `run_e2.py`에 v2.5 셀 생성이 이미 있다(방향·속도만 YAML).
- MuJoCo: 배포 저장소에 낭떠러지 코스(1.0 m 단) 추가 — 실기 하방 지도 경로(camfilter136 → heightmap119z)로 `support_end`가 같은 값을 내는지(D4).

### 7.1 A6000 1차 런(cprime_t1, aa160ba) it57: 명령 허점 → 세계 좌표 명령 (11-02 16:30)

### 7.2 2차 런(cprime_t1b, 61fdbf1) it100 리플레이: 탐색 문제 재확인 → 단계형 0 명령 + 감속 보상 (11-02 17:40)

  → 100 업데이트 동안 아무것도 배우지 못함 = v25b와 같은 **탐색 문제**. `support_end` 0 열만으로는 "멈추는 행동"이 표본화되지 않는다.
