1부. 목적과 전체 구조

1.1 목적

RBQ10 안내견 로봇이 시각장애인을 하네스로 이끌며 지하철 승강장 갭(2–26 cm, 단차 0–16 cm), 계단(5–25 cm), 경사·거친 바닥을 넘도록 한다. 블라인드 정책은 갭 앞에서 발이 빠지고 계단 앞에서 걸려 넘어진다 — 몸 앞·아래 지형을 보는 정책이 필요하다. 추가 요구:

  • 페이로드 0/6 kg(실사양 5 kg: 머리 2 + 중앙 2.5 + 후방 0.5)에서 같은 성능.
  • 핸들 외력: 계단에서 사람이 하네스를 당기거나 미는 힘(오르막 ≤200 N, 내리막 ≤150 N)을 견딘다.
  • 실제 센서: 로봇 하부 RealSense D4xx 4대(depth + IR). LiDAR는 내년 탑재 예정이며, 지금 구조는 LiDAR 경로도 같은 지도 형식으로 받는다.
  • 실시간: 정책 100 Hz, 지형 캡처 10 Hz, 로봇 CPU에서 ONNX 추론.

A0. 개념 — 전체 그림

A0.1 gd_lab이 하는 일

IsaacLab(시뮬레이터) + rsl-rl-lib 3.0.1(PPO 구현) 위에 DreamWaQ 스타일 blind 사족보행 정책을 학습시킨다. blind란 배포되는 Actor가 시각·거리 센서 없이 자기수용감각만으로 걷는다는 뜻이고, 학습 중에만 존재하는 Critic은 지형 높이·접촉력 등 특권정보를 추가로 본다. 이 저장소의 독자 설계는 커리큘럼이 아니라 CENet(맥락 추정 네트워크)과 AdaBoot(적응형 부트스트랩)이다.

왜 Critic만 특권정보를 보는가 — 비대칭 Actor-Critic Critic은 학습 중에만 쓰이고 로봇에 실리지 않는다. 그러니 실기에 없는 정보(지형 높이맵, 마찰계수, 접촉력)를 마음껏 줘도 배포에 문제가 없다. 가치추정이 정확해지면 advantage가 정확해지고, 그 결과 Actor의 경사가 덜 흔들린다. "배포될 쪽만 제약을 지키면 된다"는 것이 비대칭 구조의 요지다.

A0.2 용어 — 스텝 / 에피소드 / 이터레이션 / 배치

개념정의
스텝(step)정책이 1번 행동하는 단위. sim.dt(0.005 s) × decimation(4) = 0.02 s (50 Hz). 물리는 200 Hz로 돌지만 정책 출력은 4틱 동안 유지된다
에피소드로봇 1마리의 리셋~종료(낙상 또는 타임아웃). episode_length_s=20 s = 최대 1000스텝
num_envs병렬 로봇 수(4096). GPU 병렬도일 뿐 난이도와 무관
iteration(전 env가 num_steps_per_env=100스텝 수집) + (5 epoch × 4 minibatch 갱신) 1사이클. 정책은 100스텝 내내 고정, 끝난 뒤 한 번만 갱신
배치4096 × 100 = 409,600 transition / iteration
1 iteration ≠ 1 episode 100스텝 iteration과 최대 1000스텝 episode는 단위가 다르다. 넘어지지 않으면 한 에피소드가 약 10 iteration에 걸쳐 이어진다(v1의 48스텝 기준으로는 20.8이었다). 4096마리의 리셋 시점은 완전히 비동기라서, 어느 iteration에도 "막 리셋된 로봇"과 "900스텝째 걷는 로봇"이 섞여 있다.

A1. 액션 — Actor가 무엇을 어떻게 산출하는가

A1.1 Actor 입력 203

v1에서는 최신 1프레임(45) + code(19) = 64였다. 지금은 actor_history_steps=4로 최근 4프레임을 최신순으로 받는다.

actor_input = concat( frame[t], frame[t−1], frame[t−2], frame[t−3], code )
  = 46 × 4 + 19 = 203

code = concat( velocity.detach(), z ) = 3 + 16 = 19

정규화된 history에서 frames_idx로 뽑는다. history는 term-major로 저장되므로 (항목별 5스텝 뭉치를 이어붙인 배치), 특정 시점의 한 프레임을 꺼내려면 항목마다 흩어진 위치를 모아야 한다. 그 인덱스를 __init__에서 한 번 계산해 버퍼로 등록해 둔다. 

term-major 배치 (46 × 5 = 230)
  [ang_vel  t-4 t-3 t-2 t-1 t] [gravity t-4 … t] [cmd …] [joint_pos …] [joint_vel …] [actions …] [payload …]
   └─ 3×5=15 ─┘                 └─ 15 ─┘          15       60            60            60          5

frames_idx = 각 term 의 "t" 위치 → 그다음 "t-1" 위치 → … (최신 먼저, K=4)
latest_idx = frames_idx[:46]  (최신 1프레임만)
왜 계약은 바뀌지 않는가, 그리고 왜 체크포인트는 깨지는가 4프레임은 이미 저장 중인 5프레임 안에 들어가므로 관측 규격과 ONNX 계약은 그대로다. 반면 Actor 1층의 입력 폭이 K×46+19이므로 K를 바꾸면 체크포인트를 이어받을 수 없다. K=4가 K=1보다 낫다는 실험 근거는 저장소에 없다(4-arm 문서도 K를 다루지 않는다) — 현재로서는 "blind 기준선과 맞춘 값"으로 이해하는 것이 정확하다.

A1.2 CENet — 맥락 추정 네트워크

Actor는 자기 몸의 상태만 본다. 그런데 "지금 밟고 있는 바닥이 미끄러운가", "짐이 실려 무거운가" 같은 관측되지 않는 맥락은 걸음을 크게 좌우한다. CENet은 관측 히스토리에서 그 맥락을 추정해 잠재벡터로 압축하고, 동시에 몸통 선속도를 회귀한다.

"헤드"란 비싼 특징추출(encoder)을 한 번만 하고 그 결과 feat를 재사용해 각자 다른 걸 내는 얇은 마지막 층이다. 여기서는 셋 다 Linear 한 층씩이다.

재매개변수화 트릭이 필요한 이유 z를 분포에서 그냥 뽑으면 그 표집 연산에 경사가 흐르지 않아 encoder를 학습시킬 수 없다. z = mean + randn × exp(0.5·logvar)로 쓰면 무작위성이 randn(경사 불필요)에 격리되고, mean과 logvar는 곱셈·덧셈으로 연결돼 경사가 그대로 통과한다. 추론 시에는 표집을 끄고 z = mean을 쓴다 — 배포에서 같은 입력에 같은 출력이 나와야 하기 때문이다.

velocity.detach()에 주목. code에 들어가는 velocity는 경사를 끊어서 넣는다. Actor가 "속도 추정을 자기에게 편한 방향으로 왜곡"하지 못하게 하려는 것이다. 속도 헤드는 오직 진짜 속도와의 MSE로만 학습된다.

A1.3 AdaBoot — 속도를 참값으로 줄지 추정값으로 줄지

학습 초기에는 CENet의 속도 추정이 부정확하다. 그 값을 그대로 Actor에 넣으면 정책이 잘못된 속도 인식 위에 올라선다. AdaBoot는 동전을 던져 일정 확률로 Critic 관측의 진짜 base_lin_vel을 대신 주입한다.

CV = std(에피소드 총보상) / |mean(에피소드 총보상)|   (변동계수)
p_boot = 1 − tanh(CV)   ← 추정을 믿을 확률
p_boot ← ema × p_boot_prev + (1−ema) × p_boot_new,  ema = 0.8

성능이 들쭉날쭉하면(CV 큼) tanh(CV)가 1에 가까워져 p_boot이 0으로 내려가고 → 참값을 더 자주 주입한다. 학습이 안정되면 CV가 작아져 p_boot이 1에 가까워지고 → 자기 추정을 쓴다.

파라미터값의미

adaboot_ema0.8p_boot의 지수이동평균 계수
동전은 iteration당 한 번만 던진다 notify_iteration_done()이 플래그를 세우고, 다음 롤아웃의 첫 act에서 한 번 재표집한다. 롤아웃 중간에 바뀌면 같은 배치 안에 "참값을 본 transition"과 "추정값을 본 transition"이 섞여서, PPO가 일관되지 않은 입력 규약으로 학습하게 된다.

A3.2 GAE — advantage와 return

먼저 리턴과 가치의 정의:

Gt = Σk≥0 γk rt+k   (할인 누적보상)
V(st) ≈ E[ Gt | st ]   (Critic이 근사하는 값)

한 스텝의 예측 오차(TD error)와 그것을 지수가중으로 누적한 GAE:

δt = rt + γ V(st+1) − V(st)
ÂtGAE(γ,λ) = Σl≥0 (γλ)l δt+l

γ = 0.99  λ = 0.95  →  returnt = Ât + V(st)

λ는 편향-분산 손잡이다. λ=0이면 δt 하나만 써서 분산은 작지만 Critic 오차에 직접 휘둘린다(편향 큼). λ=1이면 몬테카를로에 가까워 편향은 없지만 분산이 크다. 0.95는 그 사이다.

타임아웃은 실패가 아니다 에피소드가 time_outs(20초 경과)로 끝난 것은 실패가 아니라 관측 중단이다. 그 시점의 미래 가치는 실제로 존재하므로 V(s_last)로 부트스트랩해서 보정한다. 반면 낙상 종료는 부트스트랩하지 않는다 — 넘어진 상태의 미래 가치는 정말로 없다. 이 구분을 놓치면 "20초를 버틴 좋은 에피소드"가 "넘어진 에피소드"와 같은 취급을 받는다.

A3.3 PPO 손실

세 항의 합을 최소화한다. r은 정책 확률비, Â는 정규화된 advantage다.

rt(θ) = πθ(at|st) / πθ_old(at|st)

Lsurrogate = −E[ min( rtÂt,  clip(rt, 1−ε, 1+ε)·Ât ) ]   ε = 0.2
Lvalue = E[ max( (V−G)², (Vclip−G)² ) ]   (clipped value loss)
Lentropy = −E[ H(π) ]

L = Lsurrogate + 1.0 · Lvalue + 0.01 · Lentropy
항계수역할
surrogate (clip)ε = 0.2확률비를 [0.8, 1.2]로 잘라 한 번에 너무 멀리 가는 것을 차단
value loss1.0Critic 회귀. clip을 쓰는 이유는 가치 추정이 한 번에 크게 튀는 것을 막기 위함
entropy0.01탐색 유지 — 실질적으로 액션 노이즈 σ의 평형값을 정한다
max_grad_norm1.0경사 노름 클리핑
entropy 계수의 물리적 의미 대각 가우시안의 엔트로피는 H = Σ log σi + 상수이므로 ∂H/∂log σ = 1이다. 즉 이 항은 매 갱신 log σ를 계수 크기만큼 일정하게 밀어올리는 힘이고, surrogate loss가 노이즈가 성능을 깎는 만큼 반대로 당긴다. σ는 그 평형점에 정착한다.

ARM 1 실측 σ ≈ 0.33. action_scale 0.25를 곱하면 관절 목표각에 1σ ≈ 4.7°이고, 다리 길이 0.4 m 기준 발 착지 위치가 약 ±3 cm 흩어진다. 14 cm 단차나 계단 노징 앞에서 결코 작지 않은 산포다.
base_contact은 노이즈가 섞인 값이다 로그의 Episode_Termination/base_contact은 탐색 노이즈가 들어간 rollout에서 측정된다. 배포되는 결정론적 정책(act_inference, σ 미적용)의 실패율은 이보다 낮다. 두 수치를 직접 비교하면 안 된다 — v1에서 결정론적 진단이 12%, 같은 시점 학습 로그가 27%였던 것이 이 차이다.

A3.4 CENet 손실 — PPO와 완전히 분리

LCENet = 1.0 · MSE(velocity, base_lin_vel.detach())
        + 1.0 · MSE(decode, next_obs.detach())  ← 비종료 행만(valid_mask)
        + β · KL,  β = 1.0

KL = −0.5 · mean( 1 + logvar − mean² − exp(logvar) )

별도 Adam(lr 1e-3)으로 독립적으로 갱신하고, Actor로 가는 code는 detach()되어 PPO 경사가 CENet에 닿지 않는다. 설계 의도는 "정책이 걷기 편한 잠재변수"가 아니라 "관측 히스토리를 잘 설명하는 잠재변수"를 만드는 것이다.

valid_mask가 왜 필요한가 재구성 타깃은 다음 스텝의 관측인데, 이번 스텝에서 에피소드가 끝났다면 그 "다음"은 리셋된 새 에피소드의 첫 관측이다. 이어져 있지 않은 두 상태를 예측하라고 시키는 꼴이라, 종료 행은 재구성 손실에서 제외한다. velocity 손실은 현재 스텝만 쓰므로 이 문제가 없다.

KL은 배치·잠재차원에 대해 평균으로 축약한다(합이 아니라). 합으로 두면 latent_dim에 따라 β의 실질 세기가 달라진다.

A3.5 적응형 KL 학습률

학습률은 고정 곡선이 아니라 KL을 목표 구간에 묶는 피드백 제어기다.

if kl_mean > desired_kl * 2.0:      # 0.02 초과 — 정책이 너무 많이 움직임
    learning_rate = max(1e-5, learning_rate / 1.5)
elif kl_mean < desired_kl / 2.0:    # 0.005 미만 — 너무 안 움직임
    learning_rate = min(1e-2, learning_rate * 1.5)

desired_kl = 0.01이므로 KL을 0.005~0.02에 묶는다. 조절이 iteration당 한 번이 아니라 미니배치마다(5 epoch × 4 minibatch = 최대 20회) 일어나므로, 한 iteration 안에서도 이론상 1.520 ≈ 3,300배까지 움직일 수 있다 — 붕괴가 아주 빠르다.

min_learning_rate = 3e-5 가 해결한 것 rsl-rl에는 1e-5 바닥이 하드코딩돼 있다. KL이 계속 크면 LR이 여기까지 밀려 내려와 주차되는데, 주차되면 정책이 안 움직이니 KL이 저절로 작아져 계기판은 정상으로 보인다 — 학습은 멎었는데 경고가 없다. v1 실측에서 한 런이 15,038~26,316 iteration 구간 약 11,000회를 이 상태로 보냈다(전체의 16%).

현재는 learning_rate setter를 가로채 max(min_lr, value)를 적용한다 — 업스트림 코드를 고치지 않고 끼워 넣는 방식이다. ARM 1 실측: 1e-5 접촉 0회, 3e-5 하한 접촉 1,196회. LR을 내리려는 압력 자체는 여전하지만 학습이 멎지 않는다.

A3.6 좌우 대칭 데이터 증강

사족보행은 좌우 대칭이므로, 한 transition을 좌우 반전하면 물리적으로 타당한 또 하나의 transition이 된다. 관측·액션의 각 항목을 대응하는 반대쪽으로 바꾸는 순열을 정의해두고 배치를 2배로 불린다 (use_data_augmentation=True). mirror loss(대칭성을 손실로 강제)는 쓰지 않는다 — 증강만으로 충분하고, 손실로 걸면 비대칭이 필요한 상황에서 방해가 된다.

안정성 교훈 (코드에 반영됨)
  • fused SDPA backward가 inf gradient의 원인(GAST v2.1 8016/8148 정지) → GAST_MATH_SDPA=1로 math kernel 강제. 대칭 증강으로 배치가 2배가 되면 CUDA attention grid 한계를 넘으므로 encoder를 8192 chunk + checkpoint로 실행.

  • CENet 이상치: 타깃(velocity/recon/history) clamp로 방어. gradient clipping은 측정상 효과 없음.

6.4 현재 한계

  • GAST 경로는 시뮬레이션 전용이다. Pilot은 --interface lo --sim이 아니면 GAST 모델을 거부한다. 학습·E1·MuJoCo·sim_docker는 모두 정답(GT) pose를 쓴다(2026-10-16 결정). 실기 pose는 camel_pilot이 발행하는 /odom(nav_msgs/Odometry, odom→base_link, 50 Hz; rosbag에서 확인)을 쓸 예정이며, 모델의 pose 입력 형식(캡처마다 world x, y, yaw)은 이미 맞춰 두었다. 실기 포팅 때 할 일: Pilot에 /odom 구독 추가, 실기 odom 오차 측정 후 pose 오차 평가(UPDATE157, POSE_ERR)로 민감도 확인, 실제 D4xx 스트림 → 매퍼 연결.
  • sidecar의 IR은 코스 GT 기하로 계산한다(실제 IR 영상 아님). depth 잡음에 stereo fill-in 패치는 없다.
  • 계약은 history 초기값을 zeros로, launcher는 RBQ_VRL_HISTORY_INIT=repeat_first를 쓴다 — 하나로 맞춰야 한다.
  • force4_classify의 갭 창과 코스 XML 표식이 약간 다르다 — 정리 필요.
