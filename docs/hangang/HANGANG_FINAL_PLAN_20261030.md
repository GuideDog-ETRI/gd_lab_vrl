# 한강 최종 학습 계획: 3906 → 후진 갭 → 통로·회전 (16노드, 2일 안)

2026-10-30 · B.S.Seo (ETRI) · 브랜치 `gh200` (v2.4 코드는 `feat/gast-narrow-turn`에서 합침)

이 문서는 한강 쪽에 전달하는 실행 계획이다. 세부 설정은 `docs/hangang/WORKORDER_LINEAGE16_20261030.md`(작업서), 회전·머리 들림 설계는 `docs/design/GAST_NARROW_V24_TURN_DESIGN.md`에 있다.

## 1. 목표

3906(Ray+IR 갭·계단)에서 시작해 **2단계, 총 48시간 안에** 다음 기능을 가진 정책 하나를 만든다.

| 기능 | 출처 | 판정 (E2 기본 조건) |
|---|---|---|
| 전진·후진 갭 건넘, 계단 | 6566 레시피 | 건넘 ≥ 6566 − 1%p, **갭 전진 머리 들림 평균 ≤ 7°, p90 ≤ 10°** (602: 10.4° / 13°) |
| 좁은 통로 통과(전진·**후진**), 막히면 서기, 막다른 길 서기 | v2.3 (602) 레시피 + v2.4 후진 통로 25 % | 602 − 1%p 이내, 후진 통로 통과 ≥ 전진 − 5%p |
| 좁은 곳 제자리 회전, 회전 불가면 멈춤 | v2.4 | 회전 성공 ≥ 90 %, 회전 불가 시 서기 ≥ 90 %, 침범 ≤ 5 % |

## 2. 시간 예산 (48 h)

16노드에서 iteration당 시간은 **실측값이 없다** (1노드 2,048 env 46.5 s, 118노드 59~64 s 사이로 추정 50~55 s). 그래서 첫 작업은 20 iteration 시험으로 시간을 재고, 그 값으로 update 수를 정한다.

| 구간 | 시간 | 내용 |
|---|---|---|
| 0. 준비 | 0.5 h | `git pull`, SIF·venv 확인, A 시험 run 20 iteration (iteration당 시간 t 측정) |
| 1. A단계 | ≤ 17 h | 3906 → 후진 갭. update 수 = min(1,200, floor(16.5 h / t)). 50 update마다 저장. it600 E2로 조기 종료 판단 |
| 2. A E2 | 1.5 h (A 끝과 겹침) | it600 저장본 E2는 A가 도는 동안 노드 1대로 따로 돌린다(사용자당 작업 5개 안). A가 끝나면 Top-5 + it1200을 노드 5대로 나눠 E2 (1 h) |
| 3. B단계 | ≤ 17 h | A 최고 모델 → v2.4 레시피(통로 + 회전 + 머리 들림). update 수 = min(1,200, floor(16.5 h / t′)), it300·600·900 E2가 평탄하면 중단, t′는 B 시험 10 iteration로 측정(지형 58열, 센서 3개라 A보다 10~20 % 느릴 수 있음) |
| 4. B E2 + MuJoCo 내보내기 | 2 h | Top-5 + 주기 저장본 E2 (노드 5대), 최고 모델 선정 |
| 합계 | **≈ 38 h** | 나머지 10 h는 대기열·재시작 여유 |

- 대기열에서 15~30분 기다리는 것이 한 번씩 있었다(10-28~29). A와 B 사이의 빈 시간을 없애려고 `watchdog_v23.sh` 방식(완료 감지 → 다음 작업 자동 제출)을 쓴다.
- 48 h를 넘길 것 같으면 **B를 줄이지 말고 A를 줄인다**(A는 600 update에서 E2로 6566 수준이면 거기서 끝내도 된다). B가 새 기능 전부를 담당한다.

## 4. 학습 파라미터

두 단계 공통: 5 epoch × 4 mini-batch, lr 고정 policy 1e-4 / terrain 3e-4, clip 0.2, γ 0.99, λ 0.95, 엔트로피 0.01, horizon 100, seed 42 + rank. 근거: 8노드 PPO 설정 비교(scale notes 8절)에서 현재 설정이 가장 좋았고, adaptive lr은 막힌 통로 침범 20.9 %로 탈락.

| 항목 | A (후진 갭) | B (통로·회전·머리 들림) |
|---|---|---|
| 스크립트 | `hangang/lineage16_a.sbatch` | `hangang/lineage16_b.sbatch` (`LINEAGE_RECIPE=v24` 기본) |
| 과제 | `Gd-GastRayIrV21Gap50BackV2` (6566과 같음) | `Gd-GastNarrowV24` |
| 출발 | 3906 `f3e7afe5…` | A 최고 모델 (`STAGE_A`, `STAGE_A_SHA256`) — LiDAR 인코더 새로, 첫 층 0 열 확장 |
| 앵커 | 없음 | A 모델 (통로·회전 타일, 머리 들림 표본 제외) |
| 램프 | 첫 작업은 과제 기본값(후진 비율 200 update, 속도 상한, 외력), 이어 학습은 0 | 0 |
| 정규화 통계 동기화 | **step마다** (`GD_LAB_NORMALIZER_DEFER=0`, 필수) | update마다 1회 |
| Top-5 기준 | `configs/gast_backgap/online_top5.json` | `configs/gast_narrow/online_top5_lineage16_b.json` (정지 ≥ 0.85, 침범 ≤ 0.05 포함). **B 200 update에 E2 기준점 + 2 SD로 다시 맞춤** |
| E2 설정 | `configs/gast_narrow/e2/v23_check_gh200.yaml` 복사, 모델만 교체 (칸당 512 env) | `configs/gast_narrow/e2/v24_turn_hangang.yaml` (v2.4 환경 `task: v24`: 회전 묶음 + 통로 전·후진 + 갭·계단 유지; 모델 경로만 교체, 기준 602). 회전 지표는 설계서 §8.1 |

**A에서 머리 들림을 미리 낮추지 않는 이유:** 6566 과제에는 `backward_nose_up`(후진만, 8° 초과 −5)만 있다. A에 전진 머리 들림 벌점을 더하면 3906 재현이 아니게 되고 비교 기준(6566)이 흐려진다. 머리 들림은 B의 `gap_nose_up` 5° + `gap_nose_peak`가 맡는다.

## 4.1 한강 실험 데이터로 본 설정 근거

**GPU당 env 수** (1노드 실측, iteration = 100 step 수집 + PPO 1회)

| GPU당 env | iteration당 | GPU당 초당 샘플 | 메모리 (실측) | 판단 |
|---|---|---|---|---|
| 1,366 | 35.1 s | 3,900 | — | 빠르지만 샘플 효율 최저 |
| **2,048** | **46.5 s** | **4,400** | 48.5 / 96 GB (236노드) | 처리량의 80 %를 유지하면서 update가 빠름 → **채택** |
| 3,584 | 87~89 s (128노드) | 4,100 | 80 / 96 GB | 노드 간 통신 포함. update가 느려 2일 조건에 불리 |
| 4,096 | 74.4 s | 5,500 | — | 처리량 최고. update 수가 성능을 좌우하는 미세 조정에는 손해 |

학습 진척은 update 횟수가 좌우한다(lr 고정 1e-4, epoch·mini-batch 고정 → update 1회당 정책 변화가 데이터 양과 무관하게 작음: surrogate loss ~1e-4, 행동 std 0.55 유지). 그래서 같은 시간에 update를 더 많이 도는 2,048이 맞다.

**epoch × mini-batch** (8노드 × 4 GPU, GPU당 3,840 env, 100 iteration, E2 칸당 512 env)

| 설정 | iteration당 | 갭 전진 20° 초과 | 막힌 통로 서기 | 막힌 통로 침범 | 열린 통로 통과 |
|---|---|---|---|---|---|
| **5 epoch × 4 mb, lr 고정** | 80 s | **3.5** | **99.3** | **0.5** | 93.7 |
| 5 × 16 | 86 s | 4.4 | 98.3 | 1.5 | 90.5 |
| 3 × 16 | 72 s | 6.0 | 92.9 | 7.1 | 97.8 |
| 3 × 16, adaptive lr | 71 s | 7.3 | 78.5 | 20.9 | 97.9 |

10 % 빠른 설정은 침범·머리 들림에서 손해가 더 크다. adaptive는 KL 평균만 보므로 일부 상황(정지)의 행동이 크게 바뀌어도 lr을 키우고, rsl-rl이 모든 그룹을 같은 lr로 덮어 써 지형 인코더의 3e-4도 사라진다 → **5 × 4, 고정 lr 유지**. 16노드 2,048 env에서 mini-batch 하나는 약 330만 샘플이다.

**필요한 iteration 수** (128노드 run, 371 → v2.3, iteration별 E2 기본 조건, %)

| 항목 | 출발 371 | it100 | it200 | it300 | it400 | it500 | it600 | it613 |
|---|---|---|---|---|---|---|---|---|
| 막다른 길 서기 | 79.6 | 93.0 | 77.1 | 95.4 | 94.3 | 94.3 | 93.7 | 96.2 |
| 열린 통로 통과 | 90.6 | 98.0 | 92.5 | 97.7 | 97.6 | 99.8 | 97.6 | 97.7 |
| 막힌 통로 침범 | 4.0 | 0.6 | 0.0 | 0.5 | 0.3 | 0.9 | 0.2 | 0.3 |
| 갭 전진 20° 초과 | 8.2 | 1.8 | 1.6 | 1.8 | 1.7 | 1.6 | 1.7 | 1.9 |
| 갭 건넘 / 계단 통과 | 97.0 / 97.3 | 97.0 / 97.2 | 97.1 / 97.4 | 96.9 / 97.3 | 97.0 / 97.2 | 96.8 / 97.2 | 97.1 / 97.0 | 96.5 / 97.2 |

- 새 기능(막다른 길, 통로, 머리 들림)은 **it100에서 거의 다 올라오고 it300 이후는 평탄**하다. it200은 정지 붕괴 구간(it160~190)의 영향. 그 뒤 300 iteration은 성능 향상이 아니라 "좋은 저장본 고르기"였다.
- 유지 항목(갭·계단)은 600 iteration 동안 변하지 않았다 → 앵커가 작동함.
- 16노드는 128노드보다 iteration당 샘플이 1/14이지만 update 수가 좌우하므로 필요한 iteration이 14배로 늘지 않는다. 같은 미세 조정을 GPU 3장·4,096 env로 한 v2.2(465 → 371)는 400 update로 충분했다.
- 따라서 **B 800~1,200 update**(it300·600·900에서 E2, 평탄해지면 중단), **A는 6566이 1,024 env로 8,000 update가 걸린 새 기술 학습이라 1,200을 상한으로 두고 it600 E2로 조기 종료를 판단**한다. A의 16노드 수치는 처음이라 근거 데이터가 없다.

**온라인 Top-5 기준**: 표본 수가 128노드의 1/14라 온라인 지표의 흔들림(SD)이 약 3.7배 커진다(128노드 갭 넘어짐 SD 0.6%p → 약 2.2%p). 고정 기준 대신 B 200 update의 E2 기준점 + 2 SD로 정한다.

## 4.2 iteration 수를 더 늘리는 것의 의미

- **B(통로·회전·머리 들림·후진 통로):** 128노드 run의 iteration별 E2가 it300 이후 평탄했으므로, 1,200을 넘겨도 성능이 더 오르지 않는다고 본다. 늘려서 얻는 것은 저장본 선택 폭뿐이다. 단, 회전과 후진 통로는 새 행동이라 128노드 데이터가 없다 → it900 E2가 it600보다 2%p 넘게 좋으면 500 update 연장(§2의 "B를 줄이지 말고 A를 줄인다" 원칙).
- **A(후진 갭):** 6566은 1,024 env로 8,000 update가 걸린 새 기술 학습이다. 16노드에서 얼마나 줄어드는지는 데이터가 없다. 1,200에서 it600 E2가 6566에 못 미치면 **A는 늘릴 가치가 있다**(48 h 조건을 풀 수 있으면 A 2,000~2,400까지). 반대로 it600에서 이미 6566 수준이면 거기서 끝낸다.
- **24 h 제한:** `lineage16_{a,b}.sbatch`는 제한 15분 전에 저장하고 멈춘 뒤, 남은 update로 자기 자신을 다시 제출한다(`--signal=B:USR1@900` + 재제출 블록; 충돌로 끝나도 저장본이 있으면 같음). 끄려면 `NO_RESUBMIT=1`. 후속 작업은 `squeue`로 확인하고, run id에 새 작업 번호가 붙는다. A의 이어 학습은 PPO 옵티마이저를 새로 만들고 램프를 재시작하지 않으며, B의 이어 학습(v2.4 → v2.4)은 PPO 옵티마이저까지 이어받는다.
