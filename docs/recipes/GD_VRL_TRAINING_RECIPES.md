# GD_VRL 학습 레서피

GuideDog RBQ10 시각 보행 정책(gd_lab_vrl)의 교사 모델 계보와, 단계마다 "무엇을 풀려고 어떤 레시피를 썼고, 어떤 보상을 더했으며,
다른 보상과 어떻게 켜고 끄는지, 무엇이 실패했고 왜였는지"를 한 곳에 모은 문서다. 결과 수치는 별도 문서
`GD_VRL_RESULTS_SHEET.md`(서버별 결과 시트)에 두고, 여기서는 판정에 쓴 값만 인용한다. 새 학습이 끝날 때마다 두 문서를 함께
갱신한다(§0.3 갱신 규칙). 출처 문서는 각 절 머리에 적었다(모두 `docs/design/`, `docs/hangang/`).

- 작성: 2026-11-02. 최신 갱신: 2026-11-03 16:30 (A6000 C′ t1h E2, 한강 A′ 종료 시점).
- 표기: "it"/"update"는 PPO 업데이트 횟수. 모델 이름은 Top-1이 저장된 업데이트 번호(예: 602 = v2.3 it602). 서버는
  **한강**(GH200, 16~236 노드), **A6000**(onvlm2, RTX PRO 6000 ×3, GPU 0·1·2만), **90.111**(5090 1장), **로컬**(5090 1장).

## 1. 모델 계보 (첫 장)

**두 세대.** 2026-10-26~31의 **이전 계보**(6566 → 1748 → 1111 → 465 → 371 → 602 → 653 → v2.5, 그리고 한강 lineage16 A = 1944)는
기술을 하나씩 쌓으며 레시피를 찾아낸 탐색 세대다. 2026-11-01부터의 **현재 계보**는 모델 계보와 단계별 레시피를 깨끗이 정리하기 위해
**3906에서 다시 시작**한다: 패턴은 **A6000 사전 검증(5,120 env × 300 it) → 한강 본 학습(131,072 env × 2,000 it)** 이고, 단계당 기술 하나
(A′ 갭+보행 → B′ 통로 → C′ 낭떠러지 → C2 회전)다. 이전 계보의 레시피와 실패 경험(§4~§11)은 현재 계보의 각 단계에 그대로 재사용된다.

### 1.2 공통 골격 (모든 단계가 공유)

- 제어 100 Hz(sim dt 0.005 × decimation 2), 에피소드 20 s, 행동 스케일 0.25, PD Kp 123/128, Kd 2.4, DelayedDCMotor.
- 관측: 고유수용 46 × 5 프레임 → CENet(z 19), 하방 지형 11 × 17 (0.1 m, 몸 기준 x ±0.8 / y ±0.5) 높이 + 가시성(+ IR 채널) →
  시간 인코더(CNN → MHA → GRU 64) → 잠재 32. 과거 프레임 오프셋 (48, 32, 16, 8, 4, 2, 1, 0) 스텝(0.48 s).
  actor 입력 235 (+ LiDAR 잠재 16 + 여유 1 + 회전 차단 1 + support_end 1 = 254 at C′). 모델 확장은 항상 **0 열 추가**로 출발 행동을 보존한다.
- PPO: horizon 100, 5 epoch × 4 minibatch, lr 정책 1e-4 / 지형·LiDAR 3e-4 고정(adaptive 금지: rsl-rl이 그룹별 lr을 덮어씀), clip 0.2,
  γ 0.99, λ 0.95, entropy 0.01. 미러 증강(`mirror_*`).
- 온라인 Top-5: 매 업데이트 비교(간격 1), 관문 파일(`configs/gast_narrow/online_top5_*.json`)은 live reload. 관문 키는 `min_*`
  외에는 0~1 값이어야 한다(v25a 교훈 §10).
- 평가: E2(`scripts/gast_narrow/e2/`, YAML로 suite·조건 선택, 고정 레벨·고정 명령, 512 env/셀), 로컬 MuJoCo(배포 저장소), E1(초기 경로).

### 1.3 갱신 규칙

1. 학습 하나가 끝나면 결과 시트(서버별 표)에 런 1행을 추가하고, 이 문서의 해당 단계 §"결과·판정"과 §"실패와 교훈"을 갱신한다.
2. 레시피를 고치면 "레시피 변경" 표에 행을 더하고, 실패한 변형은 지우지 않고 **실패 사유**와 함께 남긴다(§16 종합).
3. 한강 제출 예정 실험은 §17에 같은 형식(문제·레시피·관문)으로 미리 적고, 끝나면 본문 단계로 옮긴다.

## 2. Stage 3906 — Ray+IR 갭 50 % 교사 (출처 GAST_RAYIR_TEACHER_DESIGN_20261018)

**문제.** 맹목 DreamWaQ(DWB-38000)에 지형 인지를 더해 플랫폼 갭(≤ 0.26 m)과 계단을 건너게 한다. 인지는 하방 D4xx 4대의
레이캐스트 가시성 + IR 프록시 채널 + GAST 시간 기억.

**출발 → 결과.** DWB-38000(`blind_init`: actor·CENet·정규화 45텐서 복사, 지형 인코더 24텐서 새로, 잠재 헤드 0 초기화 → 출발 행동 =
맹목 정책) → **3906**(Top-1, 90.111, 1,024 env × 5,000 it, 16.4 h).

**레시피.**

| 항목 | 내용 |
|---|---|
| 지형 20열 | platform_gap **10열(50 %)** 폭 0.02~0.26 / 단차 0~0.16, 계단 6종·거친 지면·경사 2·울타리 각 1열 |
| 명령 | V21 속도 명령 3~7 s 재추출, 100 % heading, 20 % 정지. 갭 타일은 갭 방향 정렬, vx +0.2~0.6 전진만(`BoardingVelocityCommand`) |
| 무작위화 | 마찰 0.2~1.25, 질량 ±2 kg, 적재 0 kg 20 % / 6 kg 80 %, 밀기 10~15 s마다 Δv 0.5, 계단 손잡이 힘 오르막 ≤ 200 N·1 s / 내리막 ≤ 150 N·0.5 s |
| 관측 잡음 | 높이 1 cm + 에피소드 편향 1.5 cm, 3 % 드롭아웃, 블랙아웃(시작 0.001/step, 50~300 step, 5 % 에피소드 전체) |
| 보상(기본 보행) | 추종 lin 1.0 / ang 0.8, lin_vel_z −2, ang_vel_xy −0.15, base_height −15, 자세 roll −2 / pitch −1, 토크·가속·행동 변화 등 정규화, undesired_contacts −1, 종료 −2, hip 편차 −0.3, stand_still −0.5, stand_still_feet_contact −1, foot_clearance −1(몸 기준), feet_slipping −0.1, feet_touchdown −1, cadence_overrun −1, overspeed −1 |

| 보조 손실 | 지형 복원 0.1(갭 셀 ×5), `GAST_MATH_SDPA=1`(fused SDPA 역전파가 GAST v2.1에서 멈춤 유발) |
| Top-5 | 간격 ≥ 500 it, 갭 평균 레벨 ≥ 8.0 |

**결과·판정.** E1 v25or 갭 96.8 %, 카메라+필터 96.2 %, 계단 100 %; MuJoCo depth_ir 12시드 10/12. force4(200 N × 2 s)는 학습 범위
밖이라 약함.

**실패와 교훈.** (1) 11 × 17 / 0.1 m 격자는 좁은 통로·후방 인지에 부족 → LiDAR 지도(v1)로 보완. (2) IR은 깊이가 있는 셀에만 존재.
(3) v25or의 deepest-of-5 추출은 구덩이를 5~10 cm 넓게 보이게 한다. (4) aug149(지도 오차 증강)의 A3906 top1(5737)은 MuJoCo 1/5로
탈락 — 증강이 actor만 바꾸면 온라인 지표가 배포 성능을 보장하지 않는다.

### 2.5 배포 후보 2000/26123 교훈 (10-13~15)

26123은 GT 지도에서 계단 99.4 %지만 LiDAR 처리기 지도에서 40 %(미가시 셀 민감), 2000은 둘 다 통과. 원인은 높이 오차가 아니라
**보지 못한 셀**에 대한 반응이었다. 이후 모든 교사는 레이캐스트 가시성(보이지 않으면 0)으로 학습한다. 카메라 경로의 갭 25 %는
sensor121 스파이크(0.6 %) + min-z 축소가 원인 → camfilter136(3 × 3 이웃 중앙값 거부) 94.2 %.

## 4. Stage 1748 — narrow v1, 좁은 통로 + 머리 LiDAR (출처 GAST_NARROW_V1_DESIGN)
